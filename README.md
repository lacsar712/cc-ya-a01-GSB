# 风机偏航对中台

现场技师登记机组编号与偏航误差（度）；后台 worker 用数据库行锁认领待处理记录，按 ±1.5° 阈值写入「合格」或「偏航超差」。前端为 Lit 组件 + Vite，接口为 Quart + Hypercorn。

**入队前置**：机组必须先在「机舱方位钉死台」把机舱方位角钉死，报送时系统在同一库事务里校验钉死、把方位快照抄进单据再入队；未钉机组整单退回并记入退回说明。事后在钉死台改数不会牵动已办结旧单的方位快照与结论。

## 页面

- **总览**：提交偏航记录（技师）、对中记录列表。方位角不挂在总览尾列，点击行展开详情可见该单的钉死方位快照。
- **机舱方位钉死台**（顶栏进入）：左区待钉机组、中区已钉档案（可改数）、右区退回说明。

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/auth/login | 登录 |
| GET | /api/logs | 单据列表（含方位快照） |
| POST | /api/logs | 报送：同事务校验钉死+抄方位+入队；未钉 → 409 整单退回 |
| GET | /api/turbines | 机组清单及钉死状态 |
| GET | /api/pins | 已钉档案 |
| POST | /api/pins | 钉死（原子落库，并发争抢同一机组只一笔成功，其余 409） |
| PUT | /api/pins/{code} | 改数（不影响旧单快照） |
| GET | /api/rejections | 退回说明 |

## 启动

```bash
docker compose up --build
```

健康检查：`GET http://localhost:8199/api/health` → `{"status":"ok","service":"yaw-align-log"}`。

## 验收

1. 种子数据：机组 W01 误差 0.4° 结论「合格」；机组 W07 误差 3.2° 结论「偏航超差」（均为钉死台账上线前的历史单，无方位快照）。机组主数据 W01–W08，初始均未钉。
2. 为一号机（W01）钉方位 0.2°，再报偏航 0.8° → 进入「待处理」，数秒内 worker 判为「合格」，单据方位为 0.2°。
3. 七号机（W07）未钉直接报送 → 409「方位未钉」，整单退回并出现在钉死台右区退回说明。
4. 已办结单再查方位仍是 0.2°：钉死台把 W01 改数后，旧单快照与结论不变。
5. 两名技师并发钉同一机组：一笔落库，另一笔当场 409 拒收。
6. observer 可翻钉死表与单据方位，无钉死/改数/报送入口（接口侧 403）。

## 技术栈

- 后端：Quart、psycopg、`worker.py`（`FOR UPDATE SKIP LOCKED`）、Hypercorn
- 前端：Lit、TypeScript、Vite；生产镜像内 nginx 反代 `/api`
- 镜像源：DaoCloud 基础镜像、清华 PyPI、npmmirror npm
